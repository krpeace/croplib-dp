# 0028. 시험 실행(dry-run)도 계약 검사를 미리 돌린다 (#76 소급 5묶음 교훈)

날짜: 2026-11-09 (사용자 승인)

## 배경
- 소급 5묶음(2026-11-09): dry-run은 통과했는데 쓰기에서 `rain_mm=654.3 (범위 0~500)`으로 막혔다(결정 0027).
- 원인: 계약 검사(`check_contract`)는 `publish` 안에 있고, `publish`는 쓰기(`--write`, 곧 dry-run이 아닐 때)에서만 돈다. 그래서 시험 실행은 "쓰면 막힐 줄"을 알려 주지 못했다. 시험 실행의 목적은 쓰기 전에 문제를 보는 것이다.

## 결정
1. **쓰지 않는 실행(`write` 꺼짐 = dry-run)도 같은 계약 검사를 돌린다**(`precheck_contract`). 여섯 표를 `check_contract`로 검사해 어긋난 줄을 `r.problems`에 남긴다.
2. 어긋나면 쓰기 때와 같이 요약에 `## 문제`가 나오고 **실패(종료 코드 1)**로 끝난다. 통과하면 요약에 `계약 검사: 통과 (쓰지 않고 미리 검사함)`가 남는다. **DB에는 아무것도 쓰지 않는다**(원자료 Storage 올리기도 안 함 — 계약 실패 때 `forecast_runs`에 '실패'를 적는 `publish`의 동작도 하지 않는다).
3. 쓰기 실행의 검사는 지금처럼 `publish` 안에서만 한다(두 번 검사하지 않음).
4. **DB 칸 확인은 하지 않는다**: 쓰기는 `weather_daily.rs_source` 칸이 DB에 없으면 그 칸만 빼고 검사·올리는데(`rs_source_state`), dry-run은 DB를 읽지 않으려고 칸이 있다고 보고 검사한다. 차이는 `rs_source` 값이 허용값 밖일 때 칸이 없는 DB에서도 dry-run이 먼저 알린다는 것뿐이다(더 엄격한 쪽).
5. **알고 있는 것**: `collect.yml`의 "실패하면 5분 뒤 한 번 더"는 dry-run이 계약 검사로 실패해도 한 번 더 돈다(같은 결과, 5분 지연). 시험 실행에서만 생기는 군더더기라 두고, 필요하면 따로 고친다.

## 시험 (`tests/test_dryrun_contract.py`)
- 계약 밖 값(`rain_mm=1500`)이 있으면 dry-run이 종료 코드 1, `## 문제`에 줄 번호·값·범위를 적고 `DB 올리기: 안 함`, DB 쓰기 호출 0번.
- 정상 값이면 종료 코드 0과 `계약 검사: 통과` 문구, 실제 기록 654.3 mm는 통과.
- 쓰기(예약) 실행은 미리 검사 문구가 없고 `publish`는 한 번만 불린다. `precheck_contract` 단독 시험.
