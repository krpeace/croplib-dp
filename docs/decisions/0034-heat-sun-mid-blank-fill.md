# 0034. 적산온도·일사: 끝 날만 쓰지 않고, 가운데 낀 빈 날은 평년 채움 줄로 쓴다 (이슈 #109, 0033 개정)

날짜: 2026-11-12

## 왜 고쳤나
결정 0033(이슈 #104)은 최고·최저기온이 없는 날의 줄을 **위치와 상관없이** 올리지 않았다. 2026-11-12 09:20 실행 결과로 두 가지가 드러났다.
- 11/10은 11/11 관측이 들어와 "가운데 낀 날"이 됐는데, 줄을 안 올리니 DB에 어제 늦은 실행(0033 이전 코드)이 덮어쓴 **null 줄이 그대로 남는다**(복원되지 않음).
- 과거 지점별 기온 결측일(357줄)도 이전엔 평년 채움 줄로 올라갔는데 안 올라가 줄 수가 줄고, 요약 줄이 과거 결측일로 잡음이 됐다.

## 결정
1. 빈 날을 쓰지 않는 규칙은 **마지막 관측일 뒤(끝 날)에만** 적용한다. 끝 날을 올리면 이미 올라간 옛 값을 비운 값으로 덮기 때문이다(#104 원래 목적).
2. **마지막 관측일 앞에 낀 빈 날은 평년 채움 줄(`filled = true`, 그날 평년 하루 값, 누적에 더함)로 쓴다.** 줄이 없는 날과 같은 처리이고 0033 이전 동작이다. DB 의 옛 null 줄은 같은 키의 채움 줄로 덮이고, 기상청이 값을 다시 주면 그다음 실행이 실제 값(`filled = false`)으로 바꾼다.
3. 요약의 `빈 줄(기온 없음) 날` 줄은 **최근 7일(`BLANK_REPORT_DAYS`)의 끝 날 빈 줄만** 알린다.

## 한계 (알고 둔 것)
- **가운데 낀 날의 실제 값이 나중에 기상청에서 비워지면 평년 채움 줄로 덮인다.** 이미 올라간 실제 값이 사라진다. null 로 덮는 것보다는 낫고, 프로젝트의 채움 규칙(빠진 날은 평년 값)과 같다.
- 끝 날(마지막 관측일 뒤)의 비움은 여전히 덮어쓰지 않는다. 값이 올라올 때까지 옛 값이 남는다.
- 마지막 관측일은 최고·최저기온이 있는 마지막 날이다. 올해 관측이 하나도 없으면(`last_obs` 없음) 빈 날은 모두 끝 날로 본다.
- DB 구조·`CALC_VERSION` 변화 없음.
