# 0011. 알림 연습 (--drill)

날짜: 2026-10-26

## 배경
- 공개 판단 기준에 "실패 알림도 시험해 받았다"가 있다. 감시는 실제로 이슈를 열고 닫았지만(10/24 지연 수집 경고, 이슈 #8), 메일이 저장소 주인에게 왔는지는 확인하지 못했다. 메일이 안 왔다면 알림 설정을 고친 뒤 다시 시험할 길이 필요하다.

## 결정
- `monitor.yml` 을 손으로 실행할 때 `drill` 을 고른다 (`none` 은 평소 감시).
  - `start`: 가짜 "실패" 회차를 진짜 규칙(`check_health`)에 넣어 만든 글로 연습 이슈를 연다. 이슈를 여는 것은 평소와 같은 GitHub 기본 토큰이라 메일이 가는 경로까지 똑같이 시험된다.
  - `end`: 연습 이슈에 "정상 회복" 댓글을 달고 닫는다 (회복 메일도 확인).
- **진짜 경고와 섞이지 않게** 연습은 제목("[수집 경고] 알림 연습 (실제 문제 아님)")과 라벨("수집 경고 연습")이 다르다. 평소 감시는 "수집 경고" 라벨만 찾으므로 연습 이슈를 닫지 않고, 연습도 진짜 이슈를 건드리지 않는다.
- 연습은 **DB를 읽지도 쓰지도 않고** Supabase 키를 쓰지 않는다. 수집 기록(`forecast_runs`)에 가짜 실패를 남기지 않는다 (11/04 "3일 연속 정상" 판단을 흐리지 않기 위해).
- 같은 연습을 `start` 로 또 눌러도 새 경고가 아니므로 메일이 또 가지 않는다 (먼저 `end`).

## 알아 둘 것
- 알림 방법을 바꾸면(예: 회사 메일 발송) 이 연습으로 다시 시험한다.
