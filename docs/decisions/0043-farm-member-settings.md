# 0043. 농장 계산에 회원 설정 반영 — 관수 방식 · 뿌리 깊이 · 생육 단계 일수

2026-11-28 · 이슈 #140 · CropMon 결정 0075 · 데이터 계약 v2.6(CropMon #215)

## 왜
CropMon 1/1 회원 설정으로 회원이 농장마다 관수 방식 · 뿌리 깊이 · 생육 단계 일수를 정한다. 농장 계산은 관수효율 0.95(코드 기본값)와 작물 사전 값만 쓰고 있었다.

## 정한 것
1. **관수효율**: `farms.irrigation_method` → `irrigation_methods.efficiency`를 `Soil.ea`에 넣는다. 근권 순관수량(노지 · 시설 · 오늘 기록)과 권장 공급량(`advice_net ÷ ea`)이 모두 이 값 하나를 쓴다. 값을 못 읽으면 0.95로 대신하지 않고 그 농장을 실패로 남긴다.
2. **사전 읽는 자리**: 공개 수집기도 쓰는 `Dictionaries`에는 넣지 않고 `FarmDb.irrigation_methods()`로 실행마다 한 번, 농장 반복 앞에서 읽는다. 표를 못 읽으면 농장마다 흩어진 실패가 아니라 실행 전체가 오류로 끝나고, 로그에 표 이름과 HTTP 번호가 남으며, 대기 요청은 그대로 남는다.
3. **뿌리 깊이 · 단계 일수**: 있으면 회원 값, 비면 사전 값. 단계 일수는 넷이 함께여야 하고 Kc 기후보정 구간보다 먼저 덮어쓴다. 고를 수 있는 뿌리 깊이 값과 일수 범위는 DB check 몫이라 코드에는 "0보다 큼 · 1 이상 정수"만 둔다.
4. **작기 끝 확인은 지금 줄에만**: 시작일 + 네 단계 합 − 1이 `farm_seasons.end_date`와 다르면 그 농장 실패. `sync_farm_seasons`는 지금 줄만 다시 맞추고, 지난 줄은 옛 끝이 남거나 새 작기 시작 전날로 잘리므로 지난 줄(끝난 지 3일 안)은 확인하지 않는다.
5. **지난 줄의 설정**: 작형이 농장의 지금 작형과 같으면 회원의 `zr_m` · `l_*`를, 다르면(작물을 바꿈) 사전 값을 쓴다. 관수효율은 농장의 지금 값.
6. **공개 계산은 그대로**: 공개 관수효율 0.95(`Soil` 기본값)와 `irrigation_methods.drip` 0.95는 따로 관리한다. 같은 값일 때 설정이 빈 농장은 전과 같은 숫자가 나온다. drip 값이 바뀌면 농장 숫자만 바뀌며, 의도한 동작이다.

## 남는 한계
- 작기가 끝난 뒤 3일 안에 회원이 같은 작형의 설정을 고치면 그 지난 줄의 마지막 계산은 새 설정을 쓴다(지난 설정 기록이 DB에 없다).
- 사전 단계 일수가 바뀐 직후 `sync_all_farm_seasons()`가 돌기 전에는, 설정이 빈 농장의 지금 줄 끝이 옛 값이면 실패로 남는다. 정기 실행은 계산 전에 sync를 부른다.

## 병합 조건
새 열을 select 하므로 CropMon v2.6 SQL 실행을 확인한 뒤 병합한다.
