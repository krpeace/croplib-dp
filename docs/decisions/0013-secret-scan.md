# 0013. 자동 검사에 비밀키 검사(gitleaks) 추가

날짜: 2026-10-26 (이슈 #20)

## 배경
- 이 저장소는 공공데이터포털·기상청 키, Supabase 서버 키, 예약 실행용 토큰을 다룬다. 키가 코드나 커밋 기록에 섞여 들어가는 사고를 기계로 막는다.
- 11/04 공개 판단 기준 "저장소에 비밀키가 없다"를 자동 검사로 확인한다.
- CropMon 에서 이미 쓰는 방식(CropMon 결정 0019)을 그대로 옮긴다.
- `gitleaks/gitleaks-action` 은 조직 저장소에서 라이선스 등록을 요구한다. 그래서 쓰지 않는다.

## 결정
- **프로그램 직접 내려받기:** 공식 릴리스의 gitleaks `8.30.1`(MIT)을 받아 쓴다. 같은 릴리스의 checksums 파일로 sha256 을 검사한 뒤 실행한다. 버전은 CropMon 과 같게 고정한다.
- **별도 job `secrets`:** 기존 `check` job 과 나란히 돈다. `permissions: contents: read` 만 주고, `actions/checkout` 은 `fetch-depth: 0` 으로 전체 이력을 받는다.
- **전체 이력 검사:** `gitleaks git --redact --verbose .`
- **`--redact` 필수:** 모든 gitleaks 실행에 붙여 결과 로그에 비밀 값이 찍히지 않게 한다.
- **자체 시험:** 실행 중에 가짜 AWS 키 모양 값을 쪼개 붙여 임시 폴더에 만들고 gitleaks 가 잡는지 본다. 저장소 파일에는 온전한 값이 없다. CropMon 판보다 조여서, 종료 코드가 **정확히 1** 이고 출력에 규칙 이름(`aws-access-token`)이 있어야 통과한다. 사용법 오류로 난 실패를 탐지로 착각하지 않게 하기 위함이다.
- **`.gitleaks.toml`:** `[extend] useDefault = true`. 예외(allowlist)는 정말 가짜인 값 하나하나만, 이유 주석과 함께 넣는다. 폴더 통째로, 넓은 정규식은 쓰지 않는다. 지금은 예외가 없다.
- 워크플로의 `${{ secrets.* }}` 는 키 이름이지 값이 아니므로 그대로 둔다.

## 검사에 걸렸을 때
- 임의로 예외 처리하지 않는다. 이슈에 파일 이름·줄 번호·규칙 이름만 알린다. 값은 어디에도 쓰지 않는다.
- 진짜 키로 보이면 멈추고 사용자에게 알린다. 키 폐기·교체는 사용자가 직접 하고, 기록에서 지우는 방법은 그다음에 정한다.
- 정말 가짜로 확인된 값만, 사용자 승인 뒤 하나씩 allowlist 에 넣는다. 시험 값을 더 분명한 가짜 모양으로 바꾸는 쪽이 먼저이고, 시험 의미는 줄이지 않는다.

## 합친 뒤 사용자가 할 일
- Settings → Branches → main 보호 규칙의 필수 검사에 `secrets` 추가 (한 번 돈 뒤에 목록에 나타난다).
- Settings → Code security 에서 Secret scanning · Push protection 켜짐 확인.
