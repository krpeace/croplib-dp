# 0035. 위임과 자동화 우선: croplib-dp 채팅이 조건부로 병합하고 이슈를 닫는다 (0034 이후 상시 운영 규칙)

날짜: 2026-11-12

## 왜 바꿨나
사용자가 손으로 하는 단순 작업(병합, 이슈 닫기, 지시문 붙여넣기)이 너무 많아 시간이 오래 걸린다. 출장 때만이 아니라 평소에도 의미 없는 수작업을 줄이고 자동화하기로 했다. 사용자는 croplib-dp 채팅(Claude)에 병합과 이슈 처리를 위임했다.

## 결정
1. 작업 창(Antigravity 세션)은 계속 PR을 열고 자동 검사 통과까지만 한다. 병합하지 않는다.
2. croplib-dp 채팅은 아래 조건을 **모두** 갖춘 PR을 병합할 수 있다.
   - 자동 검사(ruff, pytest, secrets) 통과
   - 커밋 목록, 바뀐 파일, 지운 시험 줄을 직접 확인(기존 시험을 고쳤다면 이유가 PR에 있음)
   - 이슈와 무관한 커밋 없음
   - 워크플로, Actions 변수, DB 구조(마이그레이션), 삭제 작업, 스위치(`NONREP_SCENARIOS` 등) 켜기와 무관
3. 조건 하나라도 걸리면 병합하지 않고 사용자에게 남긴다.
4. croplib-dp 채팅은 완료 기준을 채운 이슈를 직접 닫고, 검토 요약을 댓글로 남긴다.
5. 채팅의 지시서는 라벨 `지시`가 붙은 이슈로 올린다. 세션은 시작할 때 그 이슈를 읽고, 결과는 같은 이슈에 댓글로 남긴다. 사용자는 붙여넣기 대신 "지시 이슈 확인" 한 줄만 말한다.
6. 사용자의 몫은 결정(스위치 켜기, 삭제, 되돌릴 수 없는 일)과 SQL Editor 실행으로 줄인다. 같은 수작업이 두 번 이상 반복되면 세션이 자동화를 이슈로 제안한다.

## 한계
- 채팅은 사용자가 메시지를 보내거나 예약된 점검 시각이 올 때만 움직인다. 상시 감시가 아니다.
- 이 위임은 croplib-dp 저장소만 해당한다. CropMon 저장소는 별도로 정한다.
- DB를 바꾸는 SQL의 자동 적용은 아직 없다(별도 결정).
