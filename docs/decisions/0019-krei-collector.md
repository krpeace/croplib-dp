# 0019. KREI 농업관측 수집기 1단계: 파일번호 키·글자 좌표 보관·이번 달+다음 달 조회·원예 4부류 감시

날짜: 2026-11-08

## 배경 및 실제 API 응답 확인 (2026-11-07, 이슈 #46)
GitHub Actions(미국 시카고 러너)에서 KREI 농업관측 API(`reportItem`, `montlyReport`, `newsReport`)와 월보 PDF 다운로드가 모두 정상 응답(HTTP 200)함을 확인했다(PR #45, 이슈 #46). 2026년 11월 실제 응답(`reportItem` 43건, `montlyReport` 12건)으로 확인한 사실은 다음과 같다.

1. **월보 발행 단위:** 품목(level 3: 사과·배 등)이 아니라 **부류(level 2) 단위로 PDF 1개**가 나온다(원예: 과일·과채·엽근채소·양념채소, 곡물·축산: 쌀·콩·감자·국제곡물·산란계·육계·해외축산).
2. **부류별 발행 주기와 종류(`title`):** 매달 모든 부류가 나오지 않으며(11월에는 버섯·한육우·젖소·돼지·오리 없음), `title`이 `월보`·`순보`(산란계)·`분기보`(해외축산)로 구분된다. **같은 달·같은 부류에 여러 건**(예: 산란계 순보+월보)이 나올 수 있다.
3. **`pdf_link`와 파일번호:** `https://aglook.krei.re.kr/main/uObserveMonth/{부류코드}/download/{파일번호}/ORGTEXT_FILE` 형식이며, 끝의 파일번호(예: `8778`)가 발행물마다 고유하다.
4. **발행 시점:** 11월호인데 쌀·콩·감자는 **10월 26일**에 먼저 등록되고 원예는 11월 2~3일에 등록되었다.
5. **품목 코드(`reportItem`):** 총 43건(3단계). `krei_item_code`는 앞자리 0이 있는 문자열(`08`)이며, 수입과일(`OVR0000000019`)·해외축산(`OVR0000000094`) 등 문서와 다르거나 새로 생긴 코드가 있고 옛 코드(쪽파 등)는 빠졌다.
6. **속보(`newsReport`):** 11월은 0건이다(속보가 없는 달은 정상).

## 결정

1. **고유 키는 파일번호(`file_id`):**
   - 같은 해·같은 달·같은 부류에도 `순보`와 `월보` 등 여러 발행물이 나오므로 `(yyyy, mm, ovr_item_code)`는 기본키가 될 수 없다. `pdf_link`에서 정규식 `/download/(\d+)/`로 뽑은 정수 `file_id`를 `krei.report`의 기본키로 쓴다.
   - 이미 `fetch_status = 'fetched'`인 건은 다시 받지 않으며, `mod_date`가 새로 채워졌거나 바뀌었을 때만 다시 받는다.
   - 품목 사전(`krei.item`)은 손으로 적지 않고 `reportItem` 응답으로만 채우되, 응답에서 빠진 옛 코드는 지우지 않고 `is_listed = false`로 남겨 과거 보고서와의 참조를 지킨다.

2. **PDF 원본 대신 글자 좌표(`pages.json.gz`) 보관:**
   - KREI 월보 PDF는 그림이 많아 1건당 5~8MB(월 12건 이상)여서 원본을 그대로 쌓으면 Supabase 무료 요금제 Storage 한도(1GB)를 1~2년 안에 넘는다.
   - 반면 `pdfplumber`로 쪽별 크기와 글자 좌표(`{"w","h","words":[[x0,top,x1,bottom,text],…]}`)만 뽑아 소수 1자리로 반올림해 gzip 압축하면 **1건당 약 40~50KB(원본의 약 1%)**로 줄어들며, 다음 단계(#4~#7)의 표·서술 파서는 이 글자 좌표만으로 언제든 다시 돌릴 수 있다.
   - PDF 원본은 실행 중 임시 폴더에만 받아 `%PDF` 시그니처·크기·`pdf_sha256`을 확인한 뒤 바로 지운다. 원본이 다시 필요하면 KREI의 `pdf_link`에서 받을 수 있고, `pdf_sha256`으로 변경 여부도 검증할 수 있다.
   - 목록 XML 원문(`krei-raw/list/{api}/{yyyy}-{mm}.xml`)은 크기가 작아 응답 형식 변경에 대비해 함께 보관한다.

3. **평소 조회는 이번 달 + 다음 달 함께:**
   - 곡물(쌀·콩·감자)처럼 다음 달 호가 이번 달 말(예: 10월 26일에 11월호 등록)에 올라오는 건을 놓치지 않도록, 기본 실행은 한국 날짜 기준 **이번 달과 다음 달**을 함께 조회한다(12월이면 다음 해 1월).
   - 소급이나 지정 조회를 위해 `--yyyy --mm` 및 `--from YYYY-MM --to YYYY-MM` 옵션을 지원한다.

4. **예약 시각과 감시 대상:**
   - 원예 월보가 주로 13~18시 KST에 등록되므로, 기존 수집 회차(물 02·17시, 적산온도 09:20)와 겹치지 않는 **매일 20:40 KST**(`krei.yml`)에 1회 실행한다.
   - 감시(`core/monitor.py`)는 매달 정기 발행되는 **원예 4부류(과일 `OVR0000000013`, 과채 `OVR0000000031`, 엽근채소 `OVR0000000008`, 양념채소 `OVR0000000036`)의 이번 달 `월보`**만 대상으로 삼아, 매달 8일 23:59 KST까지 `fetched`가 아니면 9일부터 경고를 낸다(2026년 실제 발행일 2~6일 + 여유). 발행 주기가 다른 곡물·축산·버섯은 미수집 경고를 내지 않는다.
   - 단, 어느 부류든 `fetch_status = 'failed'`인 건이 있으면 날짜와 상관없이 바로 경고(부류·파일번호·오류 첫 줄)를 낸다.

5. **스키마 분리(`krei`, `krei_api`):**
   - 수집기가 읽고 쓰는 내부 표는 `krei` 스키마(`krei.item`, `krei.report`)에 두고, 외부 공동활용 창구는 `krei_api.reports` 뷰(`fetch_status = 'fetched'`만, `security_invoker = true`)로만 안내한다.
   - 마이그레이션 SQL은 `supabase/migrations/20261108000000_krei_schema.sql`에 멱등 형식으로 두었다.

## 보충 1 (2026-11-08): 한 건씩 저장·시간 예산(25분)·시험 실행 표본 1건 제한

- **원인 확인:**
  - 첫 소급 시험 실행(`2026-01~12`, `write=false`, 실행 `#42425858862`)이 작업 제한 30분(`timeout-minutes: 30`)에 걸려 취소되었고, 마지막에 한꺼번에 `out/`과 DB를 쓰던 구조라 취소 시점에 결과 파일이 남지 않았다.
  - 1년치 소급 분량은 약 **105~130건**(2026-01~11 현재 105건, 연말까지 약 130건)인데, GitHub Actions 해외 러너에서 PDF 1건(1~10MB, 2~28쪽)을 내려받고 `pdfplumber`로 글자 좌표를 뽑는 데 요청 간격(1초)을 포함해 **1건당 평균 20~30초**(단월 실행 `#42428542526` 12건 실측 총 249초 = 건당 평균 20.8초: 내려받기 6~28초 + 좌표 추출·대기 3~19초)가 걸린다.
  - 따라서 1년치를 한 번에 다 받으려면 약 40~65분이 걸려 30분 제한을 넘길 수밖에 없었고, `write=false`(시험 실행)인데도 전 건의 PDF를 다 받으려 했던 것이 원인이었다.

- **변경 내용:**
  1. **시험 실행(`write=false`)은 목록 조회 + PDF 표본 1건만:** `write=false`일 때는 지정한 달의 목록 XML은 모두 조회·검증하되 PDF는 표본 1건만 받아 추출하고 끝내어 수 분 안에 마친다.
  2. **한 건씩 즉시 저장:** `write=true`일 때 품목 사전(`krei.item`)과 목록 XML을 먼저 올린 뒤, PDF 1건을 처리할 때마다 즉시 글자 좌표(`pages.json.gz`) 업로드와 `krei.report` 1행 upsert를 끝낸다. 중간에 작업이 취소되더라도 이미 받은 건은 DB에 `fetched`로 남아 다음 실행에서 건너뛰고 이어서 받는다.
  3. **시간 예산(기본 25분) 도달 시 정상 종료 후 이어 받기:** 실행 시작 후 25분(`--budget-minutes` 또는 환경변수 `KREI_BUDGET_MINUTES`, 기본 25분)이 지나면 새 PDF를 시작하지 않고 정상 종료(종료 코드 0)하며, 요약에 `"남은 N건, 다음 실행에서 이어 받음"`을 적는다. 남은 건이 있어도 실패나 감시 경고로 보지 않는다(예약 실행이 매일 돌기 때문에 남은 건은 자동으로 따라잡는다). 수동 실행(`workflow_dispatch`)의 `timeout-minutes`는 60분으로 두고 `budget_minutes` 입력도 열어 두었다.
  4. **`out/` 요약 파일 수시 갱신:** 목록 조회 직후와 PDF 1건 처리마다 `out/` 요약·로그 파일을 원자적으로 덮어써, 작업이 취소되더라도 `if: always()` 아티팩트 업로드·요약 단계에서 그때까지의 진행 내역이 남게 한다.

## 보충 2 (2026-11-08): 글자 없는(윤곽선·통이미지) PDF 발견과 `text_chars`·`text_status` 대응

- **발견 및 원인 분석 (`#8687`, `#8691` 등 `좌표 0.1KB` 현상):**
  - 소급 실행 중 다수의 PDF에서 추출된 `pages.json.gz`가 `0.1KB`(`words: []`, 글자 0개)인 현상이 발견되었다.
  - `#8687`(2026-05 엽근채소, 4.43MB, 12쪽)과 `#8691`(2026-05 양념채소, 9.25MB, 12쪽)을 직접 내려받아 내부 구조와 렌더링 결과를 확인한 결과:
    1. **글꼴(`/Font` 리소스):** 두 PDF 모두 전 페이지에 내장된 `/Font` 객체가 **0개**다(글꼴 인코딩·ToUnicode 문제가 아니라 텍스트 스트림 자체가 없음).
    2. **1쪽 이미지 렌더링:** 두 파일 모두 이미지로 렌더링하면 제목·본문·하단 발행정보가 사람 눈에는 선명하게 보인다.
    3. **내부 객체 구조:** 인쇄소(`Adobe InDesign 21.3` → `Adobe PDF Library 18.0`)에서 PDF를 내보낼 때 두 가지 방식으로 글자가 사라져 있었다.
       - **`#8687`(2026-05 엽근채소) → 윤곽선(Outline) 변환 PDF:** 쪽마다 벡터 곡선(`curves`)이 1,200~3,100여 개씩 들어 있는 **글자를 윤곽선(벡터 도형)으로 깨뜨린 PDF**다.
       - **`#8691`(2026-05 양념채소) → 통이미지(Full-page Raster) PDF:** 1~12쪽 모든 쪽에 `curves=0`이고 `2480×3508px`(A4 300dpi) 통이미지 1장만 들어 있는 **쪽 전체를 비트맵 이미지로 구운 PDF**다.

- **초기 조치 (`20261108010000_krei_report_text_status.sql`):**
  - `krei.report`에 `text_chars int`, `text_status text` 열을 추가하고 `--backfill-text-status` 명령으로 기존 수집 건을 채웠다.

## 보충 3 (2026-11-08): 비전 판독·OCR 미채택 결정 및 쪽 단위 판정(`no_text_pages`·`partial`)·목록 안내 체계

- **비전 판독·OCR을 하지 않기로 결정:**
  - 윤곽선·통이미지 PDF에 대해 비전 모델 판독이나 OCR을 도입하면 비용·실행 시간·숫자 오인식 위험이 커진다. 대신 **비전 판독·OCR은 하지 않고**, 판독 불가(그림 PDF) 월보 목록을 투명하게 기록·안내하고 CropMon 화면에서는 원문 PDF 링크(`pdf_link`)로 바로 보게 하는 체계를 택했다.

- **구체적 설계 및 구현:**
  1. **쪽 단위 판정 (`20261108020000_krei_unreadable_and_page_status.sql`, `compute_page_text_stats`):**
     - `krei.report`에 `no_text_pages smallint` 열을 추가하고 `text_status` 허용값을 `('ok', 'partial', 'no_text')`로 넓혔다.
     - **판정 기준:** 정상 월보는 본문 쪽당 평균 500~950자이므로, 쪽당 추출 글자 수가 **200자 미만**인 쪽을 '글자 없는 쪽'(`no_text_pages`)으로 세어:
       - 모든 쪽이 200자 미만(`no_text_pages == pages`)이면 `'no_text'`
       - 절반 이상이 200자 미만(`no_text_pages * 2 >= pages`)이면 `'partial'`
       - 나머지(`no_text_pages * 2 < pages`)는 `'ok'`로 판정한다.
     - 예: `#8703`(2026-06 과채 월보, 20쪽, 총 1,439자)은 본문·표가 그림으로 들어가 20쪽 모두 쪽당 2~127자(< 200자)이므로 `no_text_pages = 20`, `text_status = 'no_text'`로 판정된다(반면 나머지 정상 `ok` 37건은 모두 `no_text_pages <= 1`로 마지막 판권 1쪽만 107~193자이고 본문은 최소 280자 이상).
     - 2026년 1~11월 수집분(105건) 중 대상 범위(원예 4부류 + 쌀·콩·감자)의 판독 불가 월보는 총 **17건**(모두 `no_text`: 과채 6월 1건 `#8703`, 엽근채소 5~11월 7건 `#8687`·`#8705`·`#8721`·`#8731`·`#8748`·`#8769`·`#8786`, 양념채소 5~11월 7건 `#8691`·`#8696`·`#8717`·`#8727`·`#8745`·`#8763`·`#8780`, 감자 5·6월 2건 `#8693`·`#8710`)이다.
  2. **GitHub 이슈 목록 및 자동 댓글 갱신 (이슈 #57):**
     - `[krei] 판독 불가 월보 목록(그림 PDF)`(이슈 #57)에 대상 범위와 2026년 판독 불가 표(부류·월호·파일번호·쪽수·PDF 링크)를 등록했다.
     - 수집기(`collectors/krei.py`)가 대상 범위(원예 4부류 + 쌀·콩·감자)에서 `no_text` 또는 `partial` 발행물을 새로 받으면 위 이슈에 부류·월호·파일번호·PDF 링크를 댓글로 자동 추가한다. 이슈가 닫혀 있더라도 다시 열지 않고 댓글만 추가한다.
  3. **감시(`core/monitor.py`)에서 `no_text` 경고 제거:**
     - 엽근채소·양념채소 등에서 그림 PDF가 매달 반복 발행되는 현상이므로 수집 감시(`monitor`)의 `no_text` 경고는 빼고(위 2번 이슈 댓글로 갈음), `fetch_status = 'failed'` 경고와 매달 9일 00:00 KST 이후 원예 4부류 월보 미수집 경고만 유지한다.
  4. **공동활용 뷰 `krei_api.unreadable` 추가:**
     - CropMon에서 해당 부류·월호의 `"원문 보기"` 안내를 바로 띄울 수 있도록, 대상 범위(원예 4부류 + 쌀·콩·감자) 중 `text_status in ('no_text', 'partial')`인 발행물의 부류·월호·파일번호·쪽수·`pdf_link`를 노출하는 `krei_api.unreadable` 뷰(`security_invoker = true`, `anon`·`authenticated`·`service_role` 조회 권한 부여)를 추가했다.
