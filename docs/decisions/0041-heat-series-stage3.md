# 0041. 적산 계열 3단계 — 옛 표(heat_daily · sun_daily) 쓰기를 멈추고 읽는 곳을 새 표로 (이슈 #135)

날짜: 2026-11-25

## 왜 고쳤나
CropMon #207(PR #208, 결정 0072)이 2026-11-25 운영에 배포되어 화면은 이제 새 표(`heat_series_daily` · `sun_series_daily`)만 읽는다. 옛 표를 계속 쓸 이유가 없어졌고, CropMon이 "옛 표 쓰기를 멈춰도 됨"을 알렸다(순서표 #125의 3-①).
쓰기만 멈추면 옛 표를 **읽는 곳**이 낡은 표를 보게 된다: 수집 감시의 "어제 적산온도 있나", 늦은 회차(09:50)의 "이미 값이 있으면 건너뜀". 이 둘도 같은 PR에서 새 표로 옮긴다.

## 결정
1. **`publish()`는 새 표 둘만 쓴다.** 옛 표 쓰기와 옛 줄 계약 검사(`check_old`)를 뺐다. 새 표가 유일한 출력이므로 계약에 어긋나면 아무것도 올리지 않고 `problems`에 남기며, 올리기가 실패해도(어느 표든) `problems`에 남아 회차가 실패한다. 올릴 줄이 하나도 없는 것(계열 목록을 못 받음 등)도 문제다.
2. **뷰를 못 읽거나 비어 있으면 회차 실패**다. 전에는 옛 표만 올리고 실패로 남겼지만 이제 올릴 것이 없다. 문구에 원인(`뷰 crop_accum_series 읽기 실패: …` · `… 가 비어 있어 계열 목록이 없음`)이 보인다.
3. **새 표에서 옛 줄과 같은 줄 찾는 법**(CropMon 합의, 값 차이 0 확인 11/22): 옛 `heat_daily`의 `crop_id = 'common'` = 새 `heat_series_daily`의 `t_base_c = 5` · `cum_start_mmdd = '01-01'`, 옛 `sun_daily` = 새 `sun_series_daily`의 `cum_start_mmdd = '01-01'`. `read_done()`(건너뛰기)과 수집 감시(`collectors/monitor.py`)가 이 조건으로 읽는다. 건너뛰기 판단의 뜻(운영 지점 전부가 필요한 날 값을 가질 때만 건너뜀, 한 곳이라도 비었거나 읽기 실패면 건너뛰지 않음)과 감시의 읽기 모양(한 번에 지점 목록, 호출 수 그대로)은 그대로다.
4. **알림 요약(지점 줄)은 계산 경로를 건드리지 않는다.** 지점 줄(작물 공통 · 사과 · 배추 · 포도 + 햇빛 %)은 `build_station` 안의 같은 계산에서 나온다. 올리는 옛 줄을 **올리지 않을 뿐**, 그 계산 결과는 메모리에만 남겨 요약과 계산 시험이 쓴다(결과 폴더에도 옛 표 JSON 둘은 쓰지 않는다). 이유: ① 포도 숫자는 옛 작물 키(기준온도 10 · 1월 1일 누적)라 새 표(`crop_id` 없음)에서 뽑으려면 뷰에 (10, 01-01) 계열이 있어야 한다. ② 계산 경로를 건드리지 않으면 지점 줄 숫자가 안 바뀌는 것이 구조로 보장된다(병합 전 main과 같은 가짜 입력에서 글자까지 같음을 시험으로 고정, 1/1~3 경계 포함). "DB 올리기" 줄과 새해 줄의 줄 수만 새 표 줄 수로 낸다.

## 하지 않은 것
- 옛 표 지우기 · DB 구조: CropMon 몫(3-②). 옛 표의 이미 있는 줄도 건드리지 않는다.
- 옛 표 이름이 남는 곳(`io/contract.py`의 `SPECS`, `core/retention.py`의 `ROW_BYTES`, `.github/workflows/heat-sun.yml` 머리 주석)과 메모리 안의 옛 줄 모양 계산 이름(`heat_daily` · `sun_daily` 필드): CropMon이 옛 표를 지운 뒤 정리하는 후속 이슈에서 지운다. 워크플로 파일은 이 PR에서 한 줄도 건드리지 않았다.
- 알림의 "포도" 숫자는 옛 작물 키(기준온도 10, 1월 1일 누적)다. 포도 작기 누적 `(10, 04-20)`과 다르다. 알림 줄을 작형 계열로 바꿀지는 검토 채팅이 사용자와 정한다(완료 보고에 한 지점 예시).
- 계산 규칙 · 새 표 열 · 평년 기간 · 수집 시각 · 워크플로 · 변수 · 스위치.

## 병합 뒤 확인
heat-sun 09:20 회차 success, 요약 "DB 올리기"가 새 표 줄 수만 보이고 problems 없음 → 09:50 회차가 건너뜀 문구 → 12시 뒤 monitor에 `heat` 경고 없음 → 읽기 전용 조회로 옛 표 `max(date) filter (where not filled)`가 멈춰 있고 새 표는 어제까지 있음. 정상이면 CropMon이 옛 표를 지운다.
