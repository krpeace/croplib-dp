# 작업 흐름 — 검토 채팅 쪽 규칙

이 저장소의 일은 **작업창**(Antigravity)과 **검토 채팅**(croplib-dp 채팅, Claude)이 GitHub 이슈 댓글로 주고받으며 한다. CropMon 저장소의 `docs/WORKFLOW.md`와 같은 틀이다.

- **작업창의 단계**(계획 → 승인 대기 → 구현 → PR → 완료 보고 → 검토 대기 → 다음 이슈)는 `CLAUDE.md` "이슈 작업 흐름"에 있다. 작업창은 그 파일을 자동으로 읽는다. 여기에 다시 적지 않는다.
- **이 문서는 검토 채팅 쪽 규칙**이다. 작업창은 이 파일을 읽지 않아도 된다.
- 넘길 때의 "지금 상태"(진행 중 이슈 · 다음 이슈 · 부탁해 둔 확인)는 Claude 프로젝트의 인계서(`claude/croplib-dp_검토채팅_인계서_*.md`)에 둔다. 규칙은 이 문서, 상태는 인계서.
- 결정 배경: `docs/decisions/0037-issue-driven-workflow.md`.

## 1. 검토 채팅이 맡는 일

- 지시 이슈를 쓴다(라벨 `지시`). **순서표 이슈**(제목 `[순서표]`, 라벨 없음)를 따라 **하나씩** — 앞 이슈가 병합(조사 이슈는 확인)되면 다음 이슈를 올리고 순서표에 번호를 적는다. 끝나면 순서표에 체크하고 "→ PR #n 병합 (결정 00xx)"을 붙인다.
- 작업창이 단 `[작업창] 계획`을 읽고 `[검토 채팅] 승인` 또는 `[검토 채팅] 수정`을 단다.
- PR 검토: 바뀐 파일, 지우거나 바꾼 시험(기준을 낮춘 곳이 없는지), 커밋 목록, CI(`check`). 병합은 `CLAUDE.md` "개발 방식"의 조건(결정 0035)을 모두 갖췄을 때만 squash로 하고 `[검토 채팅] 병합함`. 조건에 걸리면(워크플로 파일 · 변수 · DB 구조 · 삭제 · 스위치 켜기) 사용자에게 남긴다.
- 조사 이슈(코드 변경 없음)는 `[작업창] 완료 보고`의 숫자 · 쿼리를 검토하고 `[검토 채팅] 확인함`을 단 뒤 이슈를 닫는다.
- **DB 구조는 CropMon이 주인이다.** 표 · 열 · 키가 바뀌어야 하면 이 저장소에서 고치지 않고, 사용자에게 CropMon 검토 채팅에 가져가 달라고 한다. 계약의 기준은 Claude 프로젝트의 데이터 계약(`claude/CropMon_데이터계약v2초안_261116.md`, 7판 확정)이다.
- 한 저장소는 한 검토 채팅만 맡는다. 설계 · 기준값이 바뀌어야 하면 사용자에게 알리고, 사용자가 해당 채팅에 가져간다.

## 2. 이슈 쓰는 법

- **작업창은 Claude 프로젝트 문서를 못 본다.** 이슈 본문에 왜 · 기준(수치 · 식 · 표 · 열) · 범위 · 범위 밖 · 주의 · 완료 조건을 스스로 완결되게 옮겨 적는다.
- 쓰기 전에 **지금 코드를 한 번 훑는다**(관련 모듈 위치, 이미 있는 함수 · 상수). 코드와 어긋난 전제를 쓰면 작업창이 계획에서 되묻게 된다.
- CropMon 쪽 마이그레이션이 먼저 들어가야 하는 이슈는 본문에 **선행 조건**(어느 표 · 열이 운영 DB에 있어야 하는지)을 적고, 선행이 끝나기 전에는 올리지 않는다.
- 실제 농가 위치 · 관수 기록 · 센서값, 키는 이슈 · 댓글에 쓰지 않는다(보안 규칙).

## 3. 도구 (Claude Code 세션)

- 저장소 붙이기: `add_repo`(owner `krpeace`, repo `croplib-dp`, access `push`) → `git clone --depth 1 https://github.com/krpeace/croplib-dp /home/claude/croplib-dp` → `register_repo_root`. CropMon은 읽기만 필요하면 공개 저장소라 그냥 clone한다.
- `gh`는 REST만 된다.
  - 댓글: `gh api repos/krpeace/croplib-dp/issues/<n>/comments` (쓰기는 `-F body=@파일`)
  - 새 이슈: `gh api repos/krpeace/croplib-dp/issues -f title=… -F body=@파일 -f "labels[]=지시"`
  - 이슈 본문 고치기: `gh api -X PATCH repos/krpeace/croplib-dp/issues/<n> -F body=@파일`, 닫기: `-f state=closed`
  - 열린 PR: `…/pulls?state=open`, 바뀐 파일: `…/pulls/<n>/files?per_page=100`
  - 병합: `gh api -X PUT …/pulls/<n>/merge -f merge_method=squash`
  - CI: `…/commits/<sha>/check-runs`, Actions 실행: `…/actions/runs?per_page=5`
  - PR 코드 보기: `git fetch --depth 3 origin pull/<n>/head` 뒤 `git diff <base> FETCH_HEAD`.
- 병합 권한은 세션 권한 확인에서 막힐 수 있다. 막히면 사용자에게 허용을 부탁한다.
- 커밋 · PR 끝에는 세션이 주는 표시 줄을 붙인다.

## 4. 예약 확인

- 사용자는 개입을 최소로 하길 원한다. 작업이 도는 동안 **약 30~45분 간격으로 `send_later`를 이어 건다**(작업창 기다림 120분보다 짧게). 예약 메시지에는 다음에 무엇을 보고, 무엇을 기준으로, 무엇을 할지 구체적으로 적는다.
- 계획이나 PR이 아직 없으면 30분 뒤 다시 본다. 두 번 연속 없으면 사용자에게 작업창 상태를 봐 달라고 한다. 작업창이 멈췄으면 작업창에 "CLAUDE.md 이슈 작업 흐름대로 다음 지시 이슈를 찾아 시작해"(또는 "PR #n 수정 요청 읽고 고쳐 줘")를 넣어 달라고 한다.
- 사용자에게는 병합 · 막힘 · 사용자 결정 · SQL 실행이 필요할 때만 짧게 알린다.

## 5. 새 채팅으로 넘기기

검토 채팅은 예약 확인 때마다 대화 전체를 다시 읽으므로, 대화가 길어지면 확인 한 번이 느리고 비싸진다. 채팅은 남은 용량을 정확히 볼 수 없으므로 셀 수 있는 기준으로 판단한다.

- **기준** — 하나라도 닿으면 검토 채팅이 **먼저** 넘기기를 권한다.
  - 이 채팅에서 병합한 PR이 **5개**가 됨
  - 예약 확인이 **8번** 돌아옴
  - 이 채팅을 연 지 **12시간**이 지남
  - 순서표 이슈의 **묶음(이정표)이 끝남** — 이때는 늘 넘긴다
  - 앞에서 읽은 문서 · 코드를 다시 찾게 됨
- **넘기는 때**: 검토 채팅이 하다 만 검토가 없을 때. 작업창이 계획 승인이나 PR 검토를 기다리는 중이어도 된다(새 채팅이 이어서 댓글을 달면 작업창이 그대로 읽는다).
- **넘기는 순서**
  1. 인계서의 "지금 상태"를 고친다: 열린 이슈 · PR, 작업창이 무엇을 기다리는지, 다음 이슈, CropMon 쪽 선행 상태, 사용자에게 부탁해 둔 확인, 알려진 남은 것.
  2. 이 채팅에 걸린 예약을 **지운다**(남겨 두면 옛 채팅으로 돌아온다).
  3. 사용자에게 새 채팅 첫 메시지를 드린다: "claude/croplib-dp_검토채팅_인계서_<날짜>.md 읽고 croplib-dp 검토 채팅을 이어받아줘."
- 새 채팅은 저장소를 붙이고 이 문서와 인계서를 읽은 뒤, 인계서의 "처음 할 일"부터 한다.
